# 产品定位与设计

## 定位与目标

Rig 是本地运行的开源个人 Agent harness，通过对话接受工作委托。它追求好用、精简但足够用，允许维护者长期调整提示、执行环境和外围能力，形成自己的 AI 工作环境。

当前目标用户是维护者本人，其他开发者的采用方式不构成设计约束。通用个人任务优先于编程任务，内核保持任务中立，不内置具体业务流程。

项目服务于实际使用、学习 Agent 开发和积累未来产品基础能力。取舍以维护者的真实需求为依据，不为尚未出现的需求预建通用框架。

本地执行端仅支持 macOS 和 Linux，永不支持 Windows；采用 MIT 许可证。工程现状与技术边界见[架构](architecture.md)。

## 使用方式

CLI 负责启动与管理，Web UI 是首个主要交互入口。每项工作通过对话发起，保留用户意图、Agent 的交互输出、后续修正和成果入口。

数据模型和交互协议不绑定 Web UI 或前端框架。Native Mobile、React Native 等客户端应能复用核心能力，接入时无需重新实现 Agent 业务逻辑。会话、执行状态、成果及用户操作具有一致的语义；各端可按平台能力提供不同界面和扩展特性。

1. 用户描述目标，按需提供资料、工作区和约束。
2. Agent 执行任务，向用户呈现进展、结果和需要处理的请求。
3. 用户检查结果，通过同一对话补充信息、修正目标或继续工作，也可以停止执行。
4. Agent 交付实际成果；文件成果支持预览、保存和下载。用户能够重新打开会话，查看历史并继续工作。

## 自主执行与用户控制

Agent 在授权范围内自主规划和推进委托，仅在缺少关键信息或需要授权时询问，不强制要求用户批准计划。当前不主动发现需求或发起新任务，这类能力留给未来外围扩展。

| 模式 | 执行范围与审批 |
| --- | --- |
| 安全模式 | 用户选定的资料目录只读，成果区域可写。 |
| 受保护模式，默认 | 工作区内普通操作自主执行。访问额外目录、以 root 等更高系统权限执行，以及识别出的关键危险操作，需由用户批准。 |
| Full access | Rig 层面默认允许执行和系统提权，不做逐次工具审批；实际权限与保护由操作系统、外围进程或 sandbox 决定。 |

批准仅覆盖授权的操作与范围，不隐含切换为 Full access，也不能替代操作系统认证。扩大目录授权与获得更高系统权限是不同的权限变化。

第一版由用户审批，不引入自动审查；范围与条件一致的已有授权可以复用，具体规则后续设计。危险识别不能替代执行隔离，不承诺覆盖任意命令或脚本的破坏性行为。

## 改造与个人工作环境

维护者可以调整 system prompt、适配常用模型与基础设施、改善执行环境，并按需维护外围工具或插件。具体能力由底座还是外围封装承担，根据真实需求决定。

重点探索两个产品方向，其交付阶段尚未确定：

- 远程访问。工作事实、成果和关键交互不因远程访问而缺失；只有远端客户端时，也能完成主要流程，无需另一个桌面客户端配合。
- 知识持续参与执行。用户可按需通过对话提炼知识，保存到人类可读、可检查和可修正的仓库。后续按需自动使用，以来源形式呈现实际采用的知识；知识的时效与修正影响后续使用。

知识沉淀不是每次任务的必经步骤，自动使用知识不要求逐条审批。索引、检索与入库机制后续设计。

## 首个功能 milestone

用户通过对话委托 Agent 创建并迭代文件成果，以“鹈鹕骑自行车”的 SVG 动画验收完整流程。

验收标准：

- 交付真实 SVG 文件，预览能够辨认鹈鹕骑车，并呈现持续动画。
- 用户在同一对话中提出修改，Agent 更新成果；预览、保存和下载的内容对应用户选择的成果。
- 会话保留请求、交互和成果入口，用户能够再次打开并继续工作。
- 用户能够停止执行；需要授权时，执行按当前模式等待或处理用户决定。

SVG 用例验证使用体验，不代表综合任务能力。首个 milestone 不要求完整远程访问、知识管理、通用插件系统、主动任务发现或自动配置优化。

## 能力评测

早期尝试 [SWE-bench](https://www.swebench.com/)、[Terminal-Bench](https://www.tbench.ai/) 等公开 benchmark 检查基础能力，暂不建设私有 benchmark。

比较时记录基准版本、任务子集、评估方式、模型、提示、工具、执行环境、harness 及执行成本。使用体验通过实际使用与验收判断；私有 benchmark 在有实际需求时再讨论。

## 对 Runtime 设计的要求

- 执行事实与生命周期由内核拥有；客户端通过共同的数据模型和交互协议复用能力，浏览器刷新不决定任务生命周期。
- 会话历史、模型上下文、执行记录与展示数据解耦，支持用户检查、继续、干预和停止工作。
- 通用展示数据不绑定平台或 UI 组件，客户端数据与状态逻辑独立于 UI，平台扩展保留核心交互语义。
- 执行机制落实权限模式与用户授权；保留逐步追踪具体动作的能力。debug、trace 和运行评估属于开发与运营支撑。

Runtime session 继续讨论模型接入、Agent Loop、上下文管理、工具执行、权限隔离及审批复用、会话持久化与中断恢复、客户端交互协议和外围能力接入。远程访问与知识融合的机制、交付范围另行设计。
